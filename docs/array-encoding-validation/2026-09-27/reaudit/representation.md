# Array Sort 与 packed BV 的表示关系（论证草案）

先区分两个义务：这里论证同一 GOTO-IR 内存操作的两种表示一致；
C 前端、库模型和 GOTO-IR 到状态机的整体正确性仍是独立义务。

## 1. 以元素表示说明核心关系

固定长度 N、元素宽度 w 的数组，用 Array Sort 时表示为 A，使用 packed BV
时表示为 P ∈ BV(wN)。选取低位保存第零个元素的抽象约定：

\[
R(A,P) \iff \forall i\in\{0,\ldots,N-1\},\quad
A[i]=P[wi+w-1:wi].
\]

这是有限有效下标上的关系，不是将原生总数组在所有可能下标上的值都与 P 等同。
对 int a[N]，ILP32/LP64 均有 w=32；BV(32N) 的位数不等于指针位数。

读写的表示义务为：

\[
\operatorname{readBV}(P,i)
=\operatorname{low}_w(P\mathbin{\gg_u}wi)=A[i],\qquad 0\le i<N.
\]

令 W=wN、E 将 w 位值零扩展至 W 位、
\(M_i=(2^w-1)\ll wi\) 为 W 位掩码，则

\[
P'=(P\land\neg M_i)\lor(E(v)\ll wi).
\]

必须有

\[
R(A[i\leftarrow v],P').
\]

证明要点：i 对应区间被掩码清空后填入 v；任意 j≠i 的区间与该掩码不相交，
所以其位不变。这同时给出写后读和 frame 性质。移位必须逻辑右移；完整下标与
位偏移计算不能先窄化溢出。不能用这些公式为无效 C 下标定义“返回零”的语义。

## 2. 对应当前实现的字节级关系

当前两个模式都实现统一对象字节内存。原生内存为
\(M:\mathrm{BV}_{W_{ptr}}\to\mathrm{BV}_{b}\)，b=CHAR_BIT；不是每个 int
数组独立使用元素为 BV32 的原生 Array Sort。一次 int 读取按相同目标端序组合字节。

设对象 o 有预留容量 C_o（目标 C 字节）、packed 起始字节 B_o，
\(\phi(o,j)=B_o+j\)，且所有区间 [B_o,B_o+C_o) 两两不交。
原生地址 addr(o,j) 使用既有对象号＋偏移表示。定义：

\[
R_M(M,P) \iff
\forall o,\;0\le j<C_o:\quad
M[\operatorname{addr}(o,j)]
=P[b\phi(o,j)+b-1:b\phi(o,j)].
\]

还必须同时对应：

- 每字节 written、defined 标记；它们各自以 1 位元素进行相同 packing。
- 每对象 live、zeroed、readonly 标记，以及实际大小 size。
- fresh allocation counter、halted、普通标量和 pc。
- 匹配的非确定输入选择；未初始化原始字节可以任意，但两边选择应按关系对应。

仅证明原始字节相等不够：实现通过 zeroed/written/defined 决定读取值及是否
触发模型边界。对象大小、存活状态或初始化标记错配也会改变程序行为。
多个合法别名用相同对象号与偏移，因此由 φ 的唯一性落到同一组 packed 字节。
目标端序和类型布局完全相同，逐字节关系可提升为受支持类型的整值读取关系。

## 3. 容量条件和其他前提

对所比较执行前缀中的每一次对象激活/成功分配，要求：

\[
0\le s_o\le C_o,
\]

其中 s_o 是实际对象大小。固定对象使用精确大小；运行时大小对象使用默认
1024 字节或显式配置容量。容量对隐藏复制快照同样适用，而不仅对源码数组。

还要求：

1. 目标机器、字节序、GOTO-IR、输入及源属性相同；前端未丢失访问所需的信息。
2. 使用相同成功分配次数预算；对象身份和偏移可表示，packed 宽度和位偏移不溢出。
3. 使用同一已支持内存/类型/生命周期子集；所有依赖的初始化、复制与字段 lowering
   契约成立，未以任意值代替 unsupported。
4. 有效访问按实际大小检查：读写 k 字节要求 live、对齐条件及
   0≤offset、k≤s_o、offset≤s_o−k；写还要求非只读。s_o 不能替换成 C_o。
5. 需要逐维/子对象边界性质时，两个模式采用相同的前端 instrumentation。

同一 GOTO-IR 在进入检查前已经把超宽 C 下标转换为零时，两种存储仍可能一致，
但一致性不证明原始 C 下标语义正确。README 的 O1 正是这个责任边界的实例。

## 4. 条件保持命题和证明结构

**拟证明的命题：**若两个初始状态满足上述关系，对应相同 GOTO-IR 操作，且
执行前缀满足容量、布局、身份、前端保持和支持域条件，则该前缀的对应步骤保持
关系，并对匹配的源属性和已有内存有效性检查给出相同观察结果。

证明结构：

1. 初始状态：标记和元数据初值对应；静态初始化逐次使用写保持引理。
2. load/store：分别使用读引理和写/frame 引理，再按共同字节序组合整值。
3. copy/初始化：逐字节读写保持关系，同时复制 defined 标记；重叠复制采用
   同一 snapshot lowering。不能把未初始化字节变成确定的零。
4. activate/allocate/free：对应更新实际大小、fresh、live、zeroed、readonly；
   其他对象保持。未使用的 slot 的初始元数据需满足相同不变量。
5. 分支与故障：相同路径条件守卫同一组更新；故障分类、halted、pc 与源 bad
   的抑制条件对应。最后对步骤数归纳。

这是一份实现审查和形式化工作的证明框架；本轮没有完成所有 C++ 路径的
机械化验证，也没有完成 C 前端/库模型的保持证明。

## 5. 超出容量时能够说什么

两种模式在 BV 容量内的执行前缀可以按上述关系比较。若下一次对象创建需要
s_o>C_o，BV 模型产生 model_limit 并冻结普通执行，原生 Array Sort 模型可能
仍能继续；不能再声称两条完整执行等价。

因此，仅证明 BV 模型中的源断言不可达不足以证明源程序安全。
还必须排除相关可达 model_limit，并满足既有支持域、前端和属性条件。
用 assume(s_o≤C_o) 悄悄删掉超容量路径，不等同于验证原始程序。

## 6. 本轮公式检查的准确范围

check_relation.py 使用 Z3，对索引宽度 32/64、N=1/3/5、w=1/8/32/64 的
24 个组合，构造任意原生数组、任意 packed 初值、任意合法索引和写入值，
查询读对应或写后对应关系是否存在反例；全部返回 UNSAT。

这支持列出的有限参数实例中的数学读写引理，并不证明任意参数的一般定理，
也没有直接验证 C++ helper、对象 dispatch、初始化、前端或完整状态机。
