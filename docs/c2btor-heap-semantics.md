# C2Btor 堆语义：分类规则与实现审查

> 历史审查快照（2026-09-22）：以下“当前/本轮”指统一字节模型接入前的版本。
> 2026-09-23 已用统一对象存储替换静态 malloc 对象及独立字段投影路径；
> 最新实现、仍有限制和验证结论见 [实施记录](heap-validation/2026-09-23/README.md)。

审查日期：2026-09-22。本文区分 **C 语义依据、建议的统一模型、当前实现**。
规则覆盖程度由实现是否保持语义关系判断；跑通多少个 benchmark 不构成正确性证明。

## 1. 语义依据与适用范围

以公开的 [C11 委员会草案 N1570](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)
为本轮基线，主要条款为 6.2.4、6.5、6.5.6、6.7.2.1、7.22.3 和 7.24.2。
标准要求的核心是：分配对象具有大小和生命周期；成功分配的活对象彼此独立；
malloc 内容未确定，calloc 按位清零；free 结束生命周期；realloc 成功时保留公共
前缀，失败时保留原对象。类型化访问还受布局、有效类型和别名规则约束。
零大小分配及 realloc 的零大小情况必须明确语言版本和实现选择，不能混用不同版本。

下文是针对 C2Btor 的建模设计与代码审查，不是已经完成的全 C 语义证明。
机器宽度、字节序、结构体布局来自 CBMC 的目标配置。线程、原子操作和自定义分配器
需要独立约定，不属于本轮顺序程序的模型。

**实际默认选项也属于语义。** 仓库常用 `--no-standard-checks` 会在
`cbmc_parse_optionst::set_default_analysis_flags()` 中关闭默认 malloc 失败模式，
所以当前实验通常采用“分配成功”的环境假设。它不是 C 标准保证。
如果任务允许分配失败，必须显式保留 CBMC library 的失败分支及相应选项，
并在 witness 验证中使用相同约定。关闭 bounds/pointer 检查也不等于这些行为合法。

## 2. 统一对象模型：先定义公共规则

malloc 没有“链表版本”或“树版本”。建议把所有数据结构归约为下列对象状态：

```text
Heap[o] = { live, size_bytes, bytes, initialization, type_metadata }
Pointer = { object_identity, byte_offset }
```

这里 `bytes` 是语义参照，不要求每种程序都生成巨大字节数组；类型化数组和字段拆分
可以作为优化，但必须保持与同一字节存储的对应关系。若复用有限对象槽，身份还要能
区分不同分配世代，不能让旧别名因为槽被复用而重新变成有效指针。

应统一实现/审查以下操作，而不是为每一种容器分别实现堆：

| 操作 | C2Btor 应保持的状态关系 |
|---|---|
| `allocate(n, init_policy)` | 在调用时求出 n；成功时建立独立对象和固定大小，失败时返回 NULL 并保持已有堆 |
| `address(o, offset)` | 地址计算保留根对象身份；字段地址和内部指针不是新的分配对象 |
| `load_T(p)` | 在同一对象的对应字节范围读出 T；有效性取决于存活、范围、布局、初始化和类型条件 |
| `store_T(p, v)` | 只修改目标范围；所有别名随后看到同一修改，其余对象和不重叠字段不变 |
| `copy(dst, src, n)` | 精确保持拷贝范围内的表示关系；按 memcpy/memmove 分别处理重叠条件 |
| `deallocate(p)` | 更新对象生命周期；不自动清空指向它的变量，也不自动释放它指向的其他对象 |
| `resize(p, n)` | 分开处理失败、成功、NULL 和零大小分支；成功涉及公共前缀复制及旧生命周期结束 |

基本访问条件可先写为 `live[o] && offset <= size[o] - sizeof(T)`，并先检查
`size[o] >= sizeof(T)`，避免无符号减法下溢。这还不是完整条件：需要补上对齐、
子对象边界和有效类型约束。数组步长 `sizeof(T)` 与 ABI 对齐要求不能混为一谈。
允许形成 one-past 指针与允许解引用该指针也必须分开。

例如 `p=malloc(n*sizeof(int)); n=0;` 后，`size[p.object]` 必须仍是分配时的值。
`q=p; q[0]=7;` 后，通过 p 读取同一元素必须得到 7；不能重新产生一个 nondet 值。
malloc 的未初始化内容也不能简单解释成“任何类型的读取都合法且每次重新选值”。

## 3. 按存储结构分类

| 类别 | 分配/表示规则 | 必须保持的访问关系 | 当前实现审查 |
|---|---|---|---|
| 单个标量 `T *p` | 一个对象；大小由实参决定 | `*p` 与同址别名一致 | 有类型化后备数组；本轮修复动态大小的捕获 |
| 连续数组 `T *a` | 一个对象，多个元素；n 只参与调用时大小计算 | `a[i]` 位于根偏移加 `i*sizeof(T)` | 有数组 read/write；不代表任意大对象、全部别名转换都已支持 |
| 单个结构体 | 一个根对象，成员按 ABI 布局 | `p->f` 和合法的 `&p->f` 别名指向同一子对象 | 有字段投影；本轮修复 malloc 标量字段被强制初始化为零 |
| 结构体数组 | 一个根对象，元素索引和成员偏移同时存在 | `a[i].f` 地址为 `i*sizeof(S)+offsetof(S,f)` | 不能从“支持单个结构体”推断支持；当前堆字段投影缺少统一的外层元素维度保证 |
| 结构体内数组/嵌套结构 | 成员属于根分配对象 | `p->a[i]`、取地址、整对象拷贝必须一致 | 部分字段数组已实现；字段与物理存储的一致性仍需统一 |
| 连续多维数组 `T (*)[M]` | 一块连续存储，行跨度参与地址计算 | 行指针和元素指针使用不同步长 | 有数组展平逻辑；后端数组限制及动态维度另行约束 |
| 指针数组/分段二维 `T **` | 外层指针数组和各行分别分配 | 先读行指针，再访问对应行对象；行可别名 | 不得按连续矩阵处理；依赖运行时对象分派和多对象读写 |
| 链表、树、图、哈希链 | 每次成功创建节点得到一个对象；字段保存边 | 共享节点、环、父子/前后指针都由真实指针值表达 | 静态有限分配有基础支持；循环重复分配旧实现不成立，本轮改为未展开时拒绝 |
| flexible array member | 根对象头部加动态尾区 | 以成员 offset 和实际分配边界计算尾元素 | 有常量大小具体化；动态尾区不能宣称完整支持 |
| union、类型重解释、字节视图 | 多种视图共享存储；不是各自独立字段 | 字符访问、合法别名、字节拷贝需互相可见 | 当前独立物理后备与字段投影未建立通用同步关系，属于主要缺口 |

类型从 malloc 返回值第一次被转成什么指针来推断，只能是优化提示，不能成为
内存语义本身。当前 `chase_malloc_result_type()` 采用这种提示；对多种合法视图，
必须统一到对象/字节关系，或明确拒绝尚不支持的访问组合。

## 4. 按访问方式分类

| 访问方式 | 翻译要求 |
|---|---|
| `*p`、`p[i]`、`*(p+i)` | 归一成对象和字节偏移；三种写法的等价位置共享状态 |
| `p->f`、`p[i].f` | 组合根索引和 ABI 成员偏移，不能只按字段名查一个全局状态 |
| `p->next->value` | 先读取 next 中的指针值，再按该值查询目标对象；不能沿用旧 points-to 猜测 |
| `&p->f`、内部指针 | 保留根身份和成员偏移，不能给成员独立 malloc 身份 |
| `q=p`、条件指针、交换指针 | 复制/选择指针值，不复制、移动或新建对象 |
| `void *` 往返、字符视图 | 转型不分配对象；合法视图共享已有存储 |
| 整体赋值、memcpy/memmove/memset | 与逐字段/逐字节读取一致，同时保持各操作自己的范围和重叠语义 |
| 指针比较/相减/对象大小 | 遵守对象及子对象规则；不能把打包的 tag 当成真实物理地址任意运算 |

现有 `try_store_through_runtime_pointer()` 和 `convert_dereference()` 已有运行时
tag 分派。问题是分派仍依赖类型化存储布局；解析不到对象时的一些路径会返回
`__nondet_deref` / `__nondet_address_of`，尚未统一标记成不支持。
因此“已输出 BTOR2”不能自动提升成“该访问已精确翻译”。

## 5. 增删查改与生命周期

| 用户层操作 | 归约后的语义步骤 | 重点约束 |
|---|---|---|
| 增：创建节点并插入 | allocate → 初始化字段 → 修改连接字段 | 新节点独立；每一步按原 GotoIR 顺序；失败分支不能偷偷插入节点 |
| 删：从链中摘除 | load 后继 → store 前驱/后继/根指针 | 摘除本身不释放对象；指向该对象的其他别名仍存在 |
| 删：释放节点 | deallocate | 所有别名共享失效状态；不能把所有别名变量自动置 NULL |
| 查：搜索/遍历 | load 字段与连接 → 条件跳转 | 读取不能修改堆；图的共享与环不能被树化或按分配点合并 |
| 改：值更新/重连 | store 值字段或指针字段 | 值修改不改变身份；重连不复制被指向对象；不涉及字段保持不变 |
| 扩容/缩容 | resize / realloc | 失败不破坏旧对象；成功保留公共前缀，新增长区域按初始化策略处理 |
| 销毁容器 | 保存下一指针 → free 当前 → 继续 | 不得在 free 后通过旧节点读取 next；多层结构需要显式逐层释放 |

这里不要求编码“这是树”的特殊公理。程序若通过指针赋值形成环，模型就应形成环；
若算法保持树形，那是程序要证明的性质，不能提前作为翻译假设。
free 后禁止解引用，并不要求把原字节数组清零；关键是统一的 live 检查。
丢失最后一个根指针属于可达性/泄漏问题，也不等同于调用 free。

当前 `stdlib.c` 的 free 内联模型维护 CBMC 的 `__CPROVER_deallocated` 等记录；
C2Btor 尚没有每个对象统一的 live 状态，也没有在所有 load/store 上强制生命周期
条件。本轮修正了 `pointer_object(__CPROVER_deallocated)` 被错误写死成 1 的路径，
并为动态对象判断增加运行时 tag 分派，但这仍不是完整的 free/use-after-free 模型。
realloc 的库模型还依赖 array_copy；未完成 byte lowering 的相关操作会被拒绝。
不应把当前实现描述为已经完整支持 realloc 或所有内存安全性质。

## 6. 本轮已经落地的修正

| 语义不变量 | 原实现问题 | 本轮修改 |
|---|---|---|
| 大小在分配时固定 | 从旧赋值文本重建大小，可能重新引入 nondet；大小变量后改动影响访问 | 增加每个对象的 size 状态，在 allocate 指令处捕获实参 |
| 控制流影响定义到达 | 静态大小提示跨分支/间接写仍复用 | 常量提示限于直线代码；分支、别名写、声明/销毁处清理 |
| 初始化按调用类型区分 | 忽略 allocate 的清零标志；标量字段使用默认零初值 | malloc 字段采用任意初值，calloc 初始化为全零表示 |
| calloc 大小和溢出相关 | overflow-result pair 被当作地址able struct 读取 | 显式翻译加/减/乘的 value 与 overflow 字段 |
| 活对象互相独立 | 同一循环分配点重复使用一个对象，覆盖旧节点 | 未完整展开的重复分配明确拒绝；不再称之为 sound summary |
| 展开保持执行顺序 | 可选展开器按“同一指令的各次复制”排列 | 改为完整迭代顺序；限制计数更新、控制流、取地址和回绕 |
| 截断不能伪装成完整程序 | `--unwind` 使用 PARTIAL，可直接进入循环后代码 | 改为 ASSERT_ASSUME，保留不足界限的 unwind 属性；不将其导出为 C violation witness |
| 指针属性来自实际指针 | deallocated/dead 指针对象号写死 | 删除常量特例，使用实际对象号；动态 heap 判断按 tag 分派 |
| 对象身份可追踪 | 对象 tag 分配曾依赖指令地址的 map 遍历 | 按 GotoIR 指令顺序注册分配对象 |

代码入口：

- `src/goto-btor2/goto_btor2_collect.cpp`：分配点、大小提示、布局投影与循环检测。
- `src/goto-btor2/goto_btor2.cpp` / `goto_btor2_assign.cpp`：大小快照、初始化与状态更新。
- `src/goto-btor2/expr_to_btor2_pointers.cpp`：地址、对象属性、读与访问条件。
- `src/goto-btor2/goto_btor2_unroll.cpp`：受限完整计数循环展开。
- `src/cbmc/cbmc_parse_options.cpp`：默认语义选项及显式 unwinding 策略。
- `src/ansi-c/library/stdlib.c`：malloc/calloc/free/realloc 的前端库语义。

尚需完成的是统一对象存储与字段视图、初始化/有效类型条件、live 与释放语义、
完整 realloc，以及有明确边界的动态对象池。有限池耗尽必须报告模型界限，不能
默认为真实 malloc 失败，更不能丢弃后续执行。对象号/偏移位宽也需要相应容量契约。

## 7. CBMC 实际怎样实现

前文 `Heap[o]` 是语义参照。CBMC 的普通符号执行路径采用新对象符号、SSA 更新、
指针对象号/偏移以及检查插桩，并非逐项维护同样的运行时表。

1. `src/ansi-c/library/stdlib.c` 的 malloc/calloc 先处理失败策略与 calloc 乘法溢出，
   成功分支分别调用 `__CPROVER_allocate(size, 0/1)`。
2. `goto_symext::symex_allocate()`（`src/goto-symex/symex_builtin_functions.cpp`）
   每执行一次 allocate，创建新的 `dynamic_object` 符号；动态数组长度另存一个
   fresh 的 `dynamic_object_size`，避免后续变量赋值改变对象大小。
   它利用 sizeof 信息选择标量、结构体或类型化数组，无法恢复类型时使用字节数组。
3. 分配初始化通过 `symex_assign` 写入 zero initializer 或整个对象的 nondet 值；
   返回新对象或首元素的地址。这里的 fresh 是符号执行中的分配事件，不只是源代码行号。
4. `bv_pointerst`（`src/solvers/flattening/bv_pointers.cpp`）使用对象号和偏移编码；
   offset arithmetic 保留对象号。数组/结构体写入在 `symex_assign.cpp` 变为
   with/update 或 byte_update，再进入 SSA。解引用通过 value-set 候选和指针 guard
   选择实际对象，见 `src/pointer-analysis/value_set_dereference.cpp`。
5. 普通 C 库路径的 `__CPROVER_deallocate` 非确定地记录一个被释放指针。
   `goto_check_c.cpp` 的解引用检查通过 `deallocated()` / `same_object()` 判断
   对应对象是否已释放。对于存在性错误搜索，可选择记录导致错误的那次 free，
   后续 free 选择不覆盖记录；因此这是符号检查的监视变量，不是只释放一个对象的
   实际分配器，也不能脱离对应检查公式单独解释。
6. realloc 的库模型分配、array_copy、再 free；失败分支保留旧对象。
   循环/递归中的多次分配由符号执行展开生成不同对象，受实际展开界限和编码容量约束。

C2Btor 的直接 GotoIR→BTOR2 路径保留了内联的库调用逻辑，但没有执行
`goto_symext::symex_allocate()` 及整套 SSA/dereference lowering。因此使用 CBMC
前端不等于自动继承了这部分堆语义；这正是需要逐条补齐转换规则的边界。
生命周期可选择复用完整的 CBMC 检查插桩，也可实现对象 live 状态；必须证明相应
规则对所验证性质成立，不能仅因为没有完整 live 表就断言 CBMC 的监视编码不成立。

## 8. TF 名单应怎样审查

不从 TF 标签倒推某条 C 语义必然错误，而是检查相关翻译规则：

- RQ1 的 18 个 `array-fpi` 程序使用动态大小的连续数组。先检查分配时大小、数组
  步长、类型宽度、写后读一致性和默认读取分支。已定位的旧 eqn1 电路轨迹在 N=1
  时仍能越过正确写入而读取任意默认值，和上述大小建模问题一致；这不是 C 反例。
- `nec40` / `nested_delay_nd` 需要独立检查循环、算术与控制流，不能归因于 malloc。
- RQ2 的链表程序重点检查每次创建节点的身份、next/prev 别名、摘除与释放的区分。
  静态分配点合并动态节点直接违背独立性，已经改为拒绝这一未展开模型。
- 五个 `c_dsa` 程序当前另有真实递归限制。完善 malloc 不能自动解决调用栈问题。

这些结论说明了明确的错误规则和剩余义务，**不表示 57 个任务已经全部精确建模，
也不表示已全部证明 SAFE**。用户要求转向语义审查后，新的 TF 批次已停止，保留的
部分超时/未求得反例记录不用于证明语义正确。

本轮最终源码构建成功，`git diff --check` 通过。已有最小复现只作为修正前的诊断
证据；最终改动没有用全量 benchmark 回归宣称验收，也尚未完成模拟关系的形式证明。
