# C2Btor 堆模型修改方案

日期：2026-09-22；2026-09-23 更新。状态：P0–P4 的基准存储、分配、生命周期与复制路径已落地到明确子集；P5 已完成转换覆盖复核及堆反例端到端验证，57 个 TF 的逐项语义结论尚未完成。
实际代码、容量限制和验证边界见 [实施记录](heap-validation/2026-09-23/README.md)。
现状与已修改代码见 [堆语义审查](c2btor-heap-semantics.md)。

## 1. 目标与依据

将当前分散的 malloc、字段投影和指针回退处理，收敛到可追踪的统一内存操作。
保留 C → CBMC GotoIR → BTOR2 的指令级转换，以及现有 violation witness 流程。

依据分为三层：

1. **语言契约**：以 [C11 草案 N1570 §7.22.3](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)
   为本轮分配/释放语义基线，访问规则另对照 §6.2.4、§6.5、§6.5.6、§6.7.2.1。
   分配大小、对象独立性、初始化和生命周期是必须保持的关系；零大小操作需要记录
   具体实现选择。
2. **CBMC 实现契约**：复用目标类型、布局、库函数的失败分支、溢出处理与 GotoIR
   求值顺序；参考 symex 的 fresh object、size snapshot、byte update 和 pointer guard。
   不直接运行整套有界 symex 来替代当前 BTOR2 转换。
3. **C2Btor 支持契约**：明确语言子集、机器配置、分配失败策略及有限编码容量。
   不支持的语义或达到的模型边界必须可识别，不能用不受约束的输入掩盖。

正确性论证顺序为：**定义规则 → 建立表示关系 → 推导更新 → 审查实现 → 必要回归**。
SV-COMP 最后用于检查实际覆盖和定位遗漏，不作为定义语义或证明正确性的依据。

## 2. 架构决定

```text
CBMC GotoIR（保留库模型的分支与源位置）
    ↓ 内存操作归一化
allocate / deallocate / address / load / store / copy / fill
    ↓ 统一对象表、布局与访问条件
BTOR2 状态和更新 + 源码映射 + 属性类别
    ↓
源程序错误 / 内存有效性问题 / 模型容量不足，分别解释
```

### 2.1 一个对象只有一份权威内容

语义表示：

```text
Object[o] = { kind, live, size_bytes, allocation_origin }
Memory[o, offset] = byte
Defined[o, offset] = initialization metadata
Pointer = (object_id, byte_offset)
```

- 字节路径作为基准表示，字节宽度和字节序来自 CBMC 目标配置。
- BTOR2 使用一维数组，索引拼接对象号和对象内偏移，避免引入数组套数组。
  `size`、`live` 等使用独立的标量或一维元数据数组。
- 结构体字段和数组元素都是同一对象的视图，不再各存一份互不关联的值。
- 保留类型化数组/字段优化的前提是证明视图与基准存储等价；同一根对象不能同时
  走两个独立可写表示。尚未证明的优化先不用于新的精确堆路径。
- 取地址的局部变量、全局变量也必须纳入同一别名关系，直接访问和指针访问统一
  路由；不能只修 heap，却让 `&local` 或指向全局对象的链表边读到另一份状态。
- `Defined` 不是完整 C 有效类型系统。未初始化值、padding、trap representation、
  union 重解释按子集分阶段处理；字节复制与类型化读值的前置条件分别定义。

### 2.2 动态分配采用有界 fresh object

第一版对象身份单调增加，free 后不复用身份。K 表示**总成功分配事件数上界**，
不是同时存活对象数上界。一次循环执行中的每次成功 malloc 都消耗一个新身份。

K 可由有限程序结构推导，或由显式配置给出。对象号、偏移和 one-past 指针都必须
可表示；容量检查用扩位算术，不能依靠截断或回绕。配置记录进 map/运行元数据。

达到 K 或偏移容量时触发独立的 `model_limit` 属性并停止该路径的普通执行。
它既不是程序的 malloc 返回 NULL，也不是 C violation。这样可以保留界限内的
真实反例，但不会把“只检查有限对象”包装成原程序 SAFE。

释放后复用槽、世代编号、无限次分配下的堆抽象放到后续阶段；本方案不承诺任意
无界堆。即使循环的活对象只有一个，只要总分配事件无界，第一版仍可能到达 K。
旧的完整循环展开可作为优化；动态身份不再依赖必须复制 malloc 指令。

### 2.3 保留库语义，显式标记释放事件

现有 `__CPROVER_allocate(size, zero_init)` 已经提供分配原语。free 在内联后可能只
剩监视变量赋值，所以需在转换专用的 GotoIR 中保留带来源的 deallocate 事件：

- 识别已确认来源于 CBMC 库模型的操作，不把任意同名用户函数替换成标准分配器。
- 保留库层失败、NULL 和参数检查分支；在释放真正执行的位置更新 `live`。
- 在内联前保留/归一化内部事件，内联后由 BTOR2 转换器消费；不依靠源码行号猜测。
- 与现有 `__CPROVER_deallocated` 等检查兼容，明确监视变量和对象存活状态的关系，
  避免重复释放或只更新监视变量却不更新对象状态。
- 仅改 C2Btor 的转换路径，不修改 CBMC 原有 symex/library 的默认行为。

## 3. 按操作写清翻译规则

| 规则 | 状态更新 | 必须说明的分支/前置条件 |
|---|---|---|
| R1 malloc | 捕获实参大小，分配新身份，建立未初始化对象，返回首地址 | 失败策略取自前端；已有对象不变；大小表达式只求值一次 |
| R2 calloc | 捕获乘积及溢出结果，成功后对分配范围按位清零 | 溢出和失败分支；全零字节是否对应某类型的零值取决于目标表示 |
| R3 address | 保留根对象号，组合索引与成员字节偏移 | 指针运算只更新偏移；容量、子对象范围、one-past 与可解引用分别检查 |
| R4 load | 按运行时对象号和偏移读取同一存储 | 存活、范围、对齐、支持的类型/初始化条件；合法读不能走 fresh fallback |
| R5 store | 更新写入范围和初始化元数据 | 所有别名可见；不重叠字节和其他对象不变；未访问对象不能被默认写分支修改 |
| R6 free | NULL 不操作；合法释放将 live 置假 | 必须是活的动态对象首地址；内部指针、重复释放分开报告；别名变量不自动置零 |
| R7 copy/fill | 复制或填充指定字节范围，同步初始化元数据 | memcpy 重叠限制；memmove 使用源快照；零长度不访问元素；边界运算不能溢出 |
| R8 realloc | 沿库控制流组合 allocate、前缀 copy、free | 失败保持旧对象；成功保留公共前缀；NULL/零大小规则显式记录；扩展区保持未初始化 |

每条规则同时写三项证据：源 GotoIR 操作、BTOR2 更新式、未修改状态的保持条件。
例如合法的单次写入必须满足：

```text
load_T(store_T(H, p, v), p) = v
H'[o', b] = H[o', b]，当 (o', b) 不在本次写入范围内
size'[o] = size[o]，除非本步是该新对象的分配事件
```

这些式子都有相应类型、表示与有效访问前提，不能推广到未定义行为。

动态长度清零/拷贝不伪造“一次 array write 就复制全部”。优先复用可保持语义的
CBMC lowering；需要多步时增加内部控制状态，锁存参数和必要的源快照，完成后才
推进源 GotoIR PC。原始参数和 nondet 调用只求值一次。源码属性只在相应程序边界
检查；中间步骤保留来源，witness 重建不能把它们当成重复的 C 调用。

## 4. 按数据结构和访问方式落实

| 类别 | 分配关系 | 地址/访问规则 | 增删查改的实现 |
|---|---|---|---|
| 标量、连续数组 | 一个对象，调用时固定大小 | `offset + i*sizeof(T)` | load/store 元素；扩容走 realloc |
| 结构体、嵌套结构 | 一个根对象，成员共享存储 | ABI 布局的成员 offset | 改字段只写该字段；内部指针仍指向根对象 |
| 结构体数组、成员数组 | 根索引与字段/成员索引组合 | `i*sizeof(S)+offsetof(S,f)+j*sizeof(T)` | 不同元素的同名字段不能合并 |
| 连续多维数组 | 一块连续存储 | 按实际行跨度展开偏移 | 行视图与逐元素访问一致 |
| 指针数组、分段二维数组 | 外层与各行分别分配 | 先 load 指针，再寻址行对象 | 允许不同条目指向同一行，保留共享关系 |
| 单/双链表、树、图 | 每次创建节点为一个对象 | 逐次读取 next/prev/child 指针值 | 插入/摘除是字段写，释放是 free，查找是 load+控制流 |
| flexible array member | 固定头部加实际尾区 | 从成员 offset 到真实对象边界 | 动态尾长不能靠最后一次文本赋值猜测 |
| union、字符别名、整体复制 | 多种视图共享根存储 | 按已支持的目标表示与类型规则编解码 | 独立扩展支持子集；字节路径统一不等于全部有效类型规则已解决 |

`*p`、`p[i]`、`p->f`、`&p->f`、`p->next->value`、条件指针和 `void *` 往返，都
进入统一的地址/访问接口。函数指针与整数构造地址另分类，不作为普通堆对象任意访问。
不内置“这是链表/树，因此无环”之类假设；容器形状由程序写入的边决定。

## 6. 实施顺序和完成条件

| 阶段 | 交付 | 完成条件 |
|---|---|---|
| P0 语义与诊断 | 规则编号、支持子集、配置记录、回退路径清单；区分源属性与模型属性 | 未支持访问不再静默接受为精确模型；部分模型不能进入普通 SAFE/UNSAFE 流水线 |
| P1 统一存储与访问 | 对象+偏移、byte load/store、固定分配对象、取地址变量一致性 | R3–R5 更新式与保持条件逐条对应代码；标量/数组/结构体访问共享同一内容 |
| P2 初始化与布局组合 | 大小快照、malloc/calloc、结构体数组、成员数组、多级指针 | R1–R2 成立；未确定内容、清零、索引/成员偏移不混用；未支持的表示显式拒绝 |
| P3 循环多次分配 | 有界 fresh 身份及容量属性；完整展开仅作可选优化 | 同一静态点两次成功分配不别名；超限路径不能继续当成正常程序路径 |
| P4 生命周期与复制 | free、live 检查、copy/fill、realloc；地址逃逸的局部生命周期边界 | R6–R8 成立；别名同时失效；失败分支不破坏旧对象；内部微步骤保持源步骤关系 |
| P5 TF 与 witness 收尾 | 按规则整理 57 个 TF 的结论，更新 map/运行脚本/文档 | 每项结论有规则和代码依据；候选反例才进入 CPAchecker；UNKNOWN 与 SAFE 严格区分 |

当前已有的大小快照、初始化、溢出 pair、对象注册顺序和展开修正作为待审查的基础，
不重新当成 P0–P4 已全部完成。每个阶段可分别交付和审查，避免一次替换后失去依据。

优先推进 P0 → P1 → P2，先解决 RQ1 数组及 RQ2 字段访问共同依赖的存储规则；
随后 P3 → P4 处理循环节点身份和增删管理。数组/字段优化在基准模型正确后再启用。

## 7. 结果解释与 witness

| 事件/结果 | 对外解释 |
|---|---|
| 支持范围内、有效执行前缀到达原始 violation target | C 反例候选，BtorSim 回放后生成现有 SV-COMP YAML 2.0，由 CPAchecker 验证 |
| 展开不足、对象池耗尽、偏移容量不足 | 模型边界/UNKNOWN；不作为 C violation witness |
| 未支持的类型访问或尚无合法 lowering | conversion unsupported；不输出可被误当成成功转换的产物 |
| 无效内存访问 | 独立内存属性；只验证 unreach-call 时不能混作该性质的反例，也不能无说明加 assume 删除 |
| 有限 BMC 未找到反例、超时或 backend UNKNOWN | 未得结论 |
| 后端证明原始属性及所有相关模型边界不可达，且语义/有效执行条件满足声明范围 | 才能按该声明范围报告 SAFE；不生成 invariant witness |

若无效执行的处理尚未建立与所选验证性质的一致契约，返回 UNKNOWN，不能依赖
关闭检查而声称覆盖完整 C 行为。保留用户现有默认选项，但在元数据中明确实际假设。

多属性求解不能只取日志里的一个 SAT/UNSAT 单词：模型边界可能可达，同时仍存在
界限内的真实源反例。脚本需要查询/识别具体 bad 类别，并允许独立搜索源 target。

source map 增加对象/分配来源、访问范围、内部步骤边界、属性类别与配置。它仍是
翻译元数据，不增加新的 witness 格式。SAFE 不生成不变量 witness。

## 8. 如何判断改对了

对每条规则建立 C/GotoIR 状态与 BTOR2 状态的关系 R：对象身份对应、有效字节对应、
指针对应、大小/生命周期对应、控制点对应。逐条论证：

- 支持范围内的源操作可由 BTOR2 一步或有限内部步骤完成，完成后仍满足 R。
- BTOR2 的源错误路径能还原为对应源路径；无法证明这一方向的抽象单独标识，
  不宣称所有电路反例都是 C 反例。
- 与本步无关的对象和存储范围保持不变。
- 真实分配失败和建模容量不足具有不同原因、属性及结果解释。

代码审查先覆盖规则，再做编译、解析和针对规则的必要回归。小例子用于发现实现
违背已写规则的地方；CBMC 对照也必须匹配机器模型、失败策略和展开界限。
这些检查不替代上述语义论证，更不称为已经完成机械化证明。

TF 归类：18 个 array-fpi 对照大小/偏移/读写；32 个链表类对照对象身份、别名和
生命周期；5 个 c_dsa 保留递归限制；nec40 与 nested_delay_nd 独立审查循环/算术。
拒绝一个错误模型是支持范围收缩，不能记为“修复后证明 SAFE”。实验需要新目录，
保留原始源码、模型和历史结果；按用户当前要求，方案阶段不继续批量实验。

## 9. 本方案第一版的边界

目标是顺序程序、有限编码容量、明确目标 ABI 下的精确内存操作子集。
完整递归栈、无界堆证明、对象槽无限复用、并发、任意整数到指针转换、自定义 allocator、
所有 union/effective-type/trap 细节另列扩展。首版先支持已初始化的普通整数/指针
数据读写和已定义的字节操作；其他类型只有在编解码及有效性规则就绪后纳入。

不以“可以生成 BTOR2”“validator 超时”或“TF 数量下降”替代语义完成条件。
